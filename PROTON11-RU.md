# WeHavePhones P11 Lab — эксперимент для WoW Forever

Это отдельное Android-приложение `com.wehavephones.p11lab`, а не обновление штатного
WeHavePhones. У него свои настройки, imagefs, Wine и контейнеры. Штатное приложение
не удалять. Для игры используйте уже существующую тестовую копию в общей памяти
`D:\Wow test\World of Warcraft\_forever_`, не переносите рабочую игру с C:.
Папка игры на D: общая для приложений: изменённые настройки игры/WTF тоже общие.
Не запускайте обе копии приложения одновременно с этой папкой игры.

## Что изменено

- GE-Proton 11.0-9 ARM64EC на Android/Bionic, исходники
  The412Banner/proton-wine `a01a7c58ff7d7c79fe30a34e54e1a685f4d8c2b3`.
- Перенесено необходимое native ARM64 исправление копируемых Nt*-stub:
  dispatcher читается из TEB+0x2f8; смещение проверяется C_ASSERT при сборке.
  Wine 11 уже содержит часть изменений suspend/exception из прежнего патча Wine 10.
- Сохранена задержка 100 мс при выходе native ARM64 потока, как у P10-контроля.
  Это перенос условия совместимости, а не оптимизация.
- Android owner fix собран в wineserver той же версии. DLL, SO и сервер из Wine 10
  не переносятся. Runtime собирается целиком с единым протоколом сервера.
- Профиль приложения закреплён за Proton 11 и своей парой ntdll. Повторное
  применение профиля восстанавливает P11, а не P10.
- Для первого сравнения DXVK и Turnip взяты из неизменённого WeHavePhones.
  Экспериментальные DXVK/async/readback не включены: меняется только Wine/runtime.

Исходники приложения: ashmerra/wehavephones
`f2319e428d8d02f2be88d4ca609bcae61f4fb469` (0.0.9).
Пакет GameHub ARM64X не используется. Формат .wcp и имя runtime совместимы с
WineInfo этого WeHavePhones. Новые APK подписаны тестовым ключом GitHub runner;
ключ не равен ключу официального приложения. Для последующих успешных сборок ключ
сохраняется в GitHub Actions cache; если cache удалён, для установки APK с новым
ключом потребуется удалить только P11 Lab (его контейнеры при этом удалятся).

## Проверка на планшете

1. Полностью закройте штатный WeHavePhones. Распакуйте kit и установите
   `WeHavePhones-P11-Lab.apk`. Должен появиться отдельный значок **WeHavePhones P11 Lab**.
   Если Android предлагает заменить штатное приложение — отмените установку.
2. Откройте P11 Lab, разрешите доступ к общей памяти и выполните начальную
   подготовку контейнера. После подготовки станут доступны инструменты контейнеров
   в боковом меню Runtime. Runtime уже внутри APK: отдельно ставить .wcp,
   создавать C:\DXVK-backup и копировать ntdll не нужно. Battle.net не устанавливайте:
   проверяем прямой запуск Forever.
3. В настройках/Setup должен быть профиль `p11-ge9-wow-lab`; в настройках нового
   контейнера Wine — `proton-11.0-9-arm64ec`. Откройте рабочий стол этого контейнера.
   D: должен показывать Android Download, где лежит тестовая игра.
4. В тестовом контейнере сохраните те же разрешение, масштаб рендера, DX11,
   Turnip/wrapper и отключённую VSync, что в контрольном тесте. Используйте
   `WINEDEBUG=-all`, `DXVK_HUD=version,fps,frametimes`. Не добавляйте WINENTSYNC,
   новые TU_DEBUG, CPU affinity или новые DXVK-профили в этом сравнении.
5. Откройте `D:\Wow test\World of Warcraft\_forever_\Wow-ARM64.exe` напрямую
   с аргументом `-d3d11`. Не запускайте play-readback/play-balanced: они меняют DXVK.
   Если нужен ярлык, создайте его на этот exe в P11 Lab.
6. Проверьте вход в мир, затем один и тот же маршрут/повороты камеры 2–3 минуты.
   Запишите FPS в статике, заметные рывки, прогрев и время теста. Повторите маршрут
   после прогрева кэша. Для P10 используйте отдельный контрольный тестовый контейнер
   со штатным DXVK и теми же настройками. Не заменяйте DLL рабочего контейнера.
7. Закройте P11 Lab полностью, откройте снова и проверьте, что профиль и версия
   Wine остались P11. Для возврата просто закройте P11 Lab и откройте штатный
   WeHavePhones: откат файлов в его C: не требуется.

Если запуска нет: не подставляйте ntdll из Wine 10. Для одного диагностического
запуска установите `WINEDEBUG=+loaddll,warn+seh`, сохраните журнал через штатные
средства приложения; перед измерением FPS верните `-all`. Нужны журнал, стадия
сбоя (рабочий стол/заставка/вход в мир) и скриншот выбранного Wine.

## Что проверяет сборка

GitHub Actions собирает Wine и APK. Проверяется набор функций upstream Android
runtime, ARM64 ELF/Bionic, native PE 0xaa64, машинные инструкции в экспортах
NtClose/NtDelayExecution/NtQueryInformationThread/NtWaitForSingleObject, SHA-256
runtime и согласованность DLL/SO/server внутри APK, отдельный application ID
и подпись APK. `VERIFICATION.json`, `APK-BADGING.txt` и `SHA256SUMS` входят в kit.

Эти проверки не подтверждают запуск на Xiaomi Pad 6 или прирост FPS. Их можно
установить только испытанием на планшете. Battle.net на Proton 11 не является
целью этого теста; его совместимость отдельно не подтверждена.

## Исходники и воспроизводимость

В kit входят базовый исходный tar.gz Proton, applied-source.patch (Android/GE/WoW
изменения), SUBMODULES.txt, скрипты переноса/проверки и workflow. Примените patch
к базе; подмодуль directaudio возьмите по SHA из SUBMODULES.txt:
https://github.com/The412Banner/directaudio . Внешний ntsync-android закреплён на
`7ce6435e5979b1cb5341aa4b299f31e8937fe121` в workflow. Исходники приложения и
toolchain URL закреплены там же; runtime/prepare_app.py воспроизводит изменения APK.
Лицензии исходных проектов и THIRD_PARTY_NOTICES.md сохраняют силу.

Последующие правки APK используют проверенный runtime из первой успешной сборки.
Чтобы пересобрать Proton целиком, отправьте в эту экспериментальную ветку коммит
с `[runtime-rebuild]` в сообщении. Полная цепочка сборки сохранена в workflow.
