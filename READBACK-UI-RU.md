# P11 Lab: автоматический тест DXVK A/B

Это обновление ранее установленного WeHavePhones P11 Lab. Application ID и сертификат
подписи проверяются в Actions на совпадение с первой успешной версией. Штатный
WeHavePhones и main репозитория не меняются. Proton и графический драйвер прежние.

1. Закрой P11 Lab и установи APK поверх него. Если Android предлагает удалить приложение,
   не удаляй: при удалении исчезнут его контейнеры. Сначала сообщи ошибку установки.
2. В P11 Lab открой Setup. Появится блок **DXVK: проверка плавности**.
3. При закрытом контейнере выбери **Тест A: ранняя отправка ВЫКЛ**. Открой этот же
   контейнер через Runtime, запусти тестовый Wow-ARM64.exe на D: с `-d3d11`, пройди
   маршрут 60–90 секунд, закрой игру и полностью выйди из контейнера.
4. Выбери **Тест B: ранняя отправка ВКЛ**, повтори тот же маршрут и закрой контейнер.
   Не меняй разрешение, лимит FPS, драйвер или настройки игры между A и B. Кэш сохраняется.
5. В Setup нажми **Сохранить результаты A + B в ZIP**. Кнопка покажет путь к ZIP в
   `D:\WoW-RB-logs` (при стандартном D: это Android Download/WoW-RB-logs). Пришли ZIP
   и наблюдения по FPS/рывкам. Экспорт берёт последние A/B с журналом d3d11 именно
   выбранного контейнера, пропуская пустые запуски рабочего стола.

Режим **Штатный DXVK (возврат)** вернёт исходные DLL при следующем старте контейнера.
Самостоятельно создавать папки C:, заменять DLL или запускать старые play-*.bat не нужно.
Настройки A/B хранятся отдельно для каждого контейнера. Смена режима при активной Wine
сессии запрещена: переменные окружения применяются при новом запуске контейнера.

DLL проверяются по SHA-256 и ставятся после распаковки штатного DXVK, перед запуском
Wine. Исходная пара сохраняется в `.wine/wow-rb-backup` внутри этого контейнера. Обе
DLL подготавливаются до замены; ошибка второй замены откатывает пару. В HUD A/B должна
быть отметка **WOW-CUSTOM-ARM64-RB [9f30f7325564]**. В RUN_INFO.txt сохранены режим,
Wine и хеши DLL. Каждый запуск имеет свою папку, логи не затираются перезапуском.

A и B используют одинаковые DLL, async/dedup/4 compiler workers, метрики и таймеры.
Отличается ранняя отправка копирований GPU→CPU: максимум одна дополнительная отправка
на кадр. Ожидания готовности данных, барьеры и порядок команд сохранены. Эта правка
уже собрана в DXVK; этот APK автоматизирует её установку, выбор режима и сбор результатов.
Ускорение на планшете пока не подтверждено. Метрики добавляют измерительные накладные
расходы, одинаковые в обоих режимах. A/B проверяет влияние ранней отправки внутри
этой экспериментальной сборки, а не сравнивает весь пакет со штатным DXVK.

В сборке проверяются резервные копии, повторная установка, отказ при неполной исходной
паре, откат при ошибке второй записи, выбор последних A/B для экспорта и содержимое APK.
Запуск Android-интерфейса и фактические тайминги требуют проверки на планшете.
