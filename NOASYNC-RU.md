# Проверка пропадающего интерфейса: RB без async

В обоих прежних readback-режимах был DXVK_ASYNC=1. OFF означал выключение ранней
отправки копий, а не выключение асинхронной компиляции. GPLAsync может пропускать
draw при ещё не готовом pipeline; это кандидат на причину отсутствующих элементов,
но причинная связь пока не установлена. Журнал не содержит ошибок компиляции шейдеров.

Этот пакет использует ТОЧНО ТЕ ЖЕ DLL RB 9f30f7325564; SHA-256 проверяется при упаковке.
Изменены только запускаторы: DXVK_ASYNC=0 в обоих режимах и отдельные каталоги логов.
Не нужно собирать/устанавливать новый APK, менять Wine, драйвер, разрешение или кэш.

1. Закрой игру. Распакуй пакет в новую папку D:\WoW-RB-noasync.
2. Запусти play-readback-off.bat из НОВОЙ папки.
   Если уже стоят RB DLL, restore-stock не нужен: это та же пара.
3. После входа проверь отсутствовавшие элементы интерфейса. Сейчас важна правильность
   картинки, а не FPS. При первом появлении шейдеров возможны задержки компиляции.
4. Закрой игру. Пришли результат «интерфейс восстановился / всё ещё пропадает» и файлы
   из logs\readback-off-noasync. В журнале должно быть async=0 и WOW_READBACK enabled=0.
5. ON для сравнения времени кадров запускать после проверки правильности интерфейса.
   Его файлы сохраняются в logs\readback-on-noasync; там async=0 и enabled=1.

В HUD останется WOW-CUSTOM-ARM64-RB [9f30f7325564]. Отдельной маркировки новой DLL нет,
поскольку DLL не менялись. Изменение переменной DXVK_ASYNC только в настройках контейнера
не помогло бы с прежними BAT: они сами принудительно выставляли 1. Новые выставляют 0.

Если UI остаётся неполным, причин для обвинения только async нет: тогда следует
сопоставить эту же сцену со штатным DXVK через restore-stock.bat и прямой запуск игры.
Не считать более высокий FPS при неполной отрисовке улучшением производительности.
