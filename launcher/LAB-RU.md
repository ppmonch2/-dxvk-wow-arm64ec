# ARM64 LAB: async, подавление повторов и измерение кадров

Это следующая экспериментальная сборка. Main и прежние варианты сохранены.
Изменения кода: GPLAsync 2.3.1-1, атомарный общий флаг, подавление повторных
заданий высокого приоритета для одинаковых pipeline+state, счётчики очереди
и компактная статистика Present. Дополнительно доступен предел числа компиляторов.
Обычные и низкоприоритетные задания не объединяются: запрос высокого приоритета
не должен исчезнуть из-за уже ожидающей низкоприоритетной оптимизации.

## Запуск только в тестовом контейнере
Распакуйте весь ZIP в новую папку D:\WoW-DXVK-lab. Отдельная папка на C: не нужна: штатная пара находится в stock рядом с запускатором. WINEDEBUG=-all. Локальные DLL рядом с EXE оставьте отключёнными.
Установщик допускает переход со штатных DLL, bcec80c1e075 и предыдущего async-пакета
dee2a743418f. Он сверяет обе библиотеки и резервные копии перед запуском.

| Запуск | Async | Подавление повторов | Компиляторы |
|---|---|---|---|
| play-async-off.bat | Выключен | Выключено | Авто |
| play-async-on.bat | Включён | Выключено | Авто |
| play-async-dedup.bat | Включён | Включено для High | Авто |
| play-balanced.bat | Включён | Включено для High | Не более 4 |

Для первого опыта можно запустить play-balanced.bat. Для сравнения по частям
доступны остальные режимы. Путь игры прежний:
D:\Wow test\World of Warcraft\_forever_\Wow-ARM64.exe.
Другой путь передаётся BAT-файлу первым аргументом в кавычках.

Метка HUD: WOW-CUSTOM-ARM64-LAB [<первые 12 символов коммита>].
Все профили используют ОДНУ новую пару DLL. Текущий режим записывается в логи.
Логи находятся в logs\baseline, logs\async, logs\dedup или logs\balanced.
Сначала дайте игре загрузиться, закройте меню и пройдите одинаковый маршрут
по 60-90 секунд дважды. Не сравнивайте стартовое окно загрузки с игрой в мире.

## Что измеряется
WOW_METRICS появляется примерно раз в 5 секунд в *_d3d11.log:
- mean_ms, p95_ms, p99_ms, worst_ms: интервалы между входами в CPU Present.
- over50/over100: число интервалов длиннее 50/100 мс в текущем окне.
- present_mean_ms/present_max_ms: время CPU внутри вызова Present, включая его ожидания.
- queued_total/completed_total/pending: приблизительный снимок задач компиляции.
- dedup_total: сколько повторных High-заданий не было добавлено.
- queue_peak_total: наибольшая наблюдавшаяся глубина очередей с начала процесса.
- queue_wait_us_total/worker_us_total: суммарные времена ожидания и вызовов компилятора.

Это НЕ измерение длительности работы GPU или фактического вывода кадра на экран.
Счётчики потоков читаются независимо, поэтому снимок приблизительный. Метрики
очереди суммируются внутри DLL и могут включать несколько устройств.
Гистограмма имеет шаг 1 мс и потолок 4095 мс: overflow обозначает более длинные
паузы, worst_ms сохраняет их полную длительность. p95/p99 ограничены потолком.
Процентили относятся к отдельному окну: нельзя усреднять их как общий p99 сессии.

В кадре нет записи в файл. Сводка формируется и сбрасывается в лог раз в 5 секунд.
У измерений есть собственные накладные расходы. Для игры без измерений можно
поставить WOW_DXVK_METRICS=0 в копии нужного BAT-профиля; остальные переключатели
независимы. По умолчанию без профиля новые оптимизации выключены.

## Кеш и откат
Все профили используют один каталог D:\WoW-DXVK-test-cache; запускатор его не очищает.
Это путь для штатного DXVK state cache, не обещание кеширования всех GPL-конвейеров.
Экспериментальный GPLAsync-cache остаётся выключенным. Драйверные кеши не меняются.
restore-stock.bat возвращает штатную пару при закрытой игре.

Async может временно пропускать отрисовку до готовности конвейера. Ограничение
компиляторов может как освободить CPU игре, так и увеличить ожидание новых шейдеров.
До проверки на планшете ни ускорение, ни стабильность этой сборки не установлены.
