# DXVK TILER: отправка команд с учётом тайлов Adreno

Это экспериментальная пара native ARM64 DLL (PE 0xaa64) для Wow-ARM64.exe.
Приложение, Wine/Proton и Vulkan-драйвер не изменены. Основа — наша DXVK 2.3.1.
Перенесена идея upstream 80fb7e22/a1456344 с адаптацией к старому трекеру отправок.

Режим по умолчанию выключен. При WOW_DXVK_TILER_FLUSH=1:
- Необязательные weak-hint отправки откладываются, чтобы не дробить проходы.
- Если важная strong-hint отправка была отложена, она выполняется на следующей
  смене render target/depth target, когда в очереди действительно есть команды.
- Явные Flush, Present, события и обязательные ожидания Map/fence сохранены.
- Deferred context ничего самостоятельно не отправляет при записи списка команд.
- Предыдущая принудительная ранняя отправка readback отключена в ОБОИХ режимах.

Это может уменьшить стоимость выгрузки/восстановления тайлов на Adreno, но более
редкие отправки могут также ухудшить перекрытие работы CPU/GPU. Результат на Pad 6
пока неизвестен. Store-op/discard и выбор типов памяти в этом эксперименте не менялись.
Режим включается явно для теста: строка GPU «740» через wrapper не используется
для определения физической модели. Фактические driver_id/vendor_id пишутся в лог.

## Проверка

1. Распакуй ZIP целиком в отдельную папку на D: в тестовом контейнере.
   Можно использовать уже работающий P11 Lab. Новый APK не требуется.
2. Оставь прежними драйвер, разрешение, масштаб, лимит FPS и настройки игры.
   Перед измерением выключи подробный Wine-журнал: WINEDEBUG=-all.
3. Запусти play-tiler-off.bat. После загрузки мира прогрей маршрут, затем пройди
   тот же участок/повороты камеры 60–90 секунд. Закрой игру.
4. Запусти play-tiler-on.bat и повтори маршрут. Для более надёжного сравнения
   после него повтори off: A→B→A уменьшает риск спутать эффект с прогревом/нагревом.
   Кэш не удаляй. Каждый повтор off перезаписывает его прежние логи, поэтому при
   необходимости сохрани первый off отдельно.
5. Пришли пары журналов из logs/tiler-off и logs/tiler-on, а также наблюдение FPS
   и рывков. Установщик сам проверяет и копирует DLL; папку на C: создавать не нужно.

Путь к тестовой игре уже указан: D:\Wow test\World of Warcraft\_forever_\Wow-ARM64.exe.
Другой полный путь можно передать первым аргументом BAT. Запуск всегда с -d3d11.
В HUD должна появиться WOW-CUSTOM-ARM64-TILER и короткая ревизия сборки.

## Что смотреть в журнале

- WOW_TILER enabled=0/1 — выбранный режим; early_readback=0 в обоих случаях.
- WOW_TILER boundary_submit_executed — первая фактическая отправка новым путём.
- WOW_TILER_STATS — раз в 300 кадров: context_flushes_total,
  weak_suppressed_total, boundary_flushes_total. Это счётчики D3D11-контекста,
  а не аппаратный счётчик vkQueueSubmit. Без активности boundary путь может
  только подавлять слабые подсказки; нельзя объявлять пользу по одному enabled=1.
- WOW_METRICS/WOW_DXGI_METRICS — интервалы кадров и ожидания из прежних проб.

Обе стороны используют одинаковые DLL, async/dedup, четыре compiler workers и
одинаковую диагностическую нагрузку. Это сравнение одной правки, не всего пакета
со штатным DXVK. Режим off сохраняет прежний путь необязательных отправок;
дополнительные счётчики/редкая запись диагностических строк присутствуют в обоих.

При ухудшении выбери play-tiler-off.bat; restore-stock.bat возвращает исходные DLL.
Основной рабочий контейнер не использовать. Успех сборки и тестов установщика
не подтверждает запуск или прирост производительности на планшете.
